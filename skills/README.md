# skills/ — 仓库内可复用流程约定

本目录存放**固化下来的操作流程**：把那些「步骤固定、验收标准固定、会重复发生」的工作写成 `SKILL.md`，让 AI 每次执行同样的路径，产出可复现、可审查。

规则源头是 `AGENTS.md`；本文件只说明**什么值得固化、怎么固化**。

> **本阶段状态：只写约定与计划，不写具体 SKILL.md。**
> 每个 skill 必须等它依赖的接口设计在对应的 `specs/` 里定案之后才能落地——否则会把尚未确认的设计固化进流程里，反而更难改。

---

## 1. 值得固化的判据

三个条件**同时**满足才值得写成 skill：

1. **步骤固定** —— 每次都要按同样的顺序做同样的事，没有需要临场判断的分支；
2. **验收标准固定** —— 做完了怎么算做对，是明确的、可检查的；
3. **重复发生** —— 未来还会做第二次、第三次（例如"再接一个邮件供应商"）。

只要有一条不满足，就不要固化：

- **一次性任务**（例如"把仓库从 A 迁到 B"）→ 写在 `specs/` 的对应 spec 里；
- **需要人类决策的任务**（例如"选哪个审查方案"）→ 按 `AGENTS.md` §6 留下决策记录：跨特性底座走 `docs/research/` 下对应主题册，某特性的设计结论走该特性的 `specs/<特性>/design.md`；
- **步骤还在变动的流程** → 先跑几次，稳定了再固化。过早固化会把错误流程制度化。

## 2. 目录与命名

```
skills/
├── README.md                    ← 本文件
├── add-review-provider/
│   └── SKILL.md
├── add-smtp-provider/
│   └── SKILL.md
└── offline-release-and-deploy/
    └── SKILL.md
```

- 目录名：`英文小写短横线`，动词开头，描述**要达成的结果**（`add-xxx`、`verify-xxx`、`release-xxx`）。
- 每个 skill 一个目录，入口文件固定为 `SKILL.md`。
- **目录名与文件名一律 ASCII，内容用中文。**
- **当前 `skills/` 下只有本文件，尚不存在任何 `SKILL.md`**：上图只是命名约定，不是现状。

---

## 3. `SKILL.md` 的结构约定

每个 `SKILL.md` 必须包含以下小节，顺序固定：

| 小节 | 写什么 |
|---|---|
| **触发条件** | 什么情况下该用这个 skill。写成可识别的信号（例如"需要接入一个新的审查供应商时"），不要写"需要时使用"。 |
| **前置检查** | 动手前必须确认的事：依赖的 spec 是否已确认、接口是否已定案、必要的配置与环境是否就绪。**未通过前置检查就必须停下来**，不要"边做边补"。 |
| **步骤** | 有序的操作清单，每步是一条可执行的动作，标注要改的文件路径。不要写"适当地处理"。 |
| **验收** | 怎么证明做完了：要跑的命令、要看到的输出、要更新的文档与 spec。 |
| **常见错误** | 已知的坑与错误做法（例如"忘记在 `providers/*/base.py` 里注册新实现"）。这一节是 skill 最有价值的部分，认真写。 |
| **关联** | 依赖的 spec 编号与该特性的 `design.md`、`docs/research/` 下相关的主题册、涉及的其他 skill。 |

---

## 4. 与 specs / docs 的关系

- **skill 不定义接口**。接口定义在 `specs/`，skill 只是"按已定案的接口新增一个实现"的操作流程。
- **skill 可以被多次执行**；`specs/` 里的一个 spec 通常只对应一个特性的一次实现。
- 若执行 skill 时发现接口设计与 spec 不符：**先改 spec 并重新确认**，不要顺着 skill 改接口。
- 新增 skill 本身不需要更新决策记录；但如果 skill 里包含"改表结构""改 API 契约""换依赖"这类动作，那些动作本身仍须按 `AGENTS.md` §6 更新它的落点（本特性 `design.md` 或 `docs/research/` 下对应主题册）的决策段。

## 6. 新增 skill 的流程

1. 确认判据（§1）三条都满足；
2. 确认它依赖的接口已在 `specs/` 中定案（状态为 `已确认` 或之后）；
3. 建目录 `skills/<名字>/SKILL.md`，按 §3 的结构写；
4. 在本文件 §5 的表格里登记它，并填上真实依赖的 spec 路径；
5. 若流程里包含不可逆动作，按 `AGENTS.md` §6 更新它的落点（本特性 `design.md` 或 `docs/research/` 下对应主题册）的决策段。
