# 代码风格规范（评审与自查的唯一出处）

> **本文件是「代码长什么样」的唯一出处**：写代码的 AI 在跑门禁前逐条自查，评审（含 code-review）以它为 Standards 依据逐条判定。
> **只写机器查不出的部分**——格式、行宽、import 顺序、命名大小写、现代类型语法等已由 ruff / mypy 强制，不在此重复；分层规则见 `architecture.md`，测试规则见 `testing.md`，本文件只给指针。

每一条都写成**可判定的问句**：写完代码后逐条自问，答「否」就改；评审时每条答「否」即一条 finding。

---

## 1. 函数与结构

1. 单个函数是否 ≤ 50 行、只做一件事？（超出通常意味着该拆——优先按「业务步骤」拆，不按「代码行数」拆。）
2. 单个函数的分支复杂度是否可控（圈复杂度不超过 10）？嵌套超过 3 层就是信号。
3. `try` 块是否只包住会抛异常的那一句？（包住整个函数体会把不相关的错误也吞进同一个处理器。）
4. 文件、连接、锁、session 是否都用 `with` / `async with` 管理，保证任何退出路径都释放？
5. 对可能很大的集合做成员判断，是否用 `set` / `dict`（O(1)）而不是在循环里对 `list` 做 `in`？
6. 有没有重复三处以上的代码段？有就提一个公共函数，但**不要为了消重把两个语义不同的东西强行合并**。
7. 布尔量命名是否带前缀（`is_active` / `has_permission` / `can_retry`），让调用点读起来像句子？

## 2. 异常与错误处理

1. 抛出与捕获的是否都是**具体异常类型**？`raise Exception(...)`、`except:`、`except Exception` 一律不允许。
2. 每个捕获处是否要么处理、要么用 `logger.exception(...)` 留下栈，再决定转译或上抛？（静默吞掉 = 隐患。）
3. 异常类是否定义在它所属的层（api / service / providers 各自定义自己的错误类型），而不是全仓库共用一个？
4. 异常信息是否只描述「发生了什么、怎么定位」（用邮件 ID 等引用），不含敏感内容？（红线见 `AGENTS.md` §8 第 4 条，此处只提示自检。）

## 3. 异步与 I/O

1. 所有 I/O（数据库、SMTP/IMAP、HTTP）是否走 `async` 路径？async 函数里出现同步阻塞调用（同步 sleep、同步 HTTP、CPU 密集循环）即是错误。
2. 并发任务是否有超时与取消语义，而不是裸 `await` 一个可能永不返回的操作？
3. 时间是否一律取带时区的 `datetime`（UTC），没有裸的 `datetime.now()`？（此条同时是 `AGENTS.md` §7 的硬约束，列在这里供自查。）

## 4. HTTP 接口层（`src/vs_email_forwarding/api/`）

1. 路由函数是否只做三件事：请求校验、调 service、组装响应？出现了业务判断或 SQL 就是放错层（判定依据见 `architecture.md`）。
2. 请求与响应是否都是 Pydantic 模型（`schemas/`），没有裸 dict 进出？
3. 预期错误是否用 `HTTPException` + 明确状态码抛出，而不是靠 500 兜底？
4. 路由是否声明了响应模型与状态码，让 OpenAPI 文档可直接读？

## 5. 注释与 docstring

1. 每个公开函数/类是否有一段中文 docstring，说明它**做什么业务**（而不只是复述函数名）？
2. 注释是否解释「为什么这么写」（业务规则、约束出处），而不是逐句翻译代码？逐句翻译型注释应删除。
3. 凡是约束来自某个文档的代码（幂等、重试、`Reply-To` 等），是否在注释里给出了出处指针（如 `AGENTS.md` §8、`specs/0001-.../design.md`），让下一个人能查到依据？

## 6. AI 生成代码的附加自查

1. 每个 `import` 的第三方包是否都在 `docs/research/03-dependencies-and-toolchain.md` 登记过？**没有就停下来问所有者，禁止凭记忆 `pip install`**——模型会编造包名（幻觉包名是已量化的风险），也会用过时 API。
2. 写下的每个库 API 用法，是否以**仓库已安装版本**为准核对过，而不是凭训练记忆？拿不准就先看 `.venv` 里的真实签名。
3. 期望值、配置项、魔法数字是否全部有出处（`constants.py`、`.env`、specs），没有「随手填一个合理的」？
4. 改动是否触碰到未定项（`docs/open-questions.md`）或既有决策？触碰即停，先问所有者。
