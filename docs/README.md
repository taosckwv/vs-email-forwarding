# 文档入口

> **本文件是文档的唯一入口。** 它只回答三件事：**去哪儿看**、**怎么读**、**怎么写**。
> **AI 协作规则**的唯一真源是仓库根的 `AGENTS.md`，不在这里；本文件不重复任何规则与结论。

---

## 1. AI 先读顺序

按这个顺序读，不要跳：

1. **`AGENTS.md`** —— 规则与边界（必读；不读它会违反硬约束）。
2. **本文件** —— 文档地图。
3. **`docs/research/` 下对应的主题册** —— **跨特性底座**的结论真源（见 §3 的表）；**某特性的设计结论**见该特性的 `specs/<特性>/design.md`。
4. **`docs/open-questions.md`** —— 未定项清单。**动手前先确认你要做的不在其中**；在其中就停下来问所有者。
5. **`specs/<当前特性>/`** —— 若该特性已有规格与设计（`spec.md` / `design.md`）。

## 3. 文档分区（唯一的分区表）

| 路径 | 角色 | 只放 | 不放 |
|---|---|---|---|
| `../AGENTS.md` | **规则唯一真源** | 规则、硬约束、目录职责、编码约定、决策记录流程 | 结论复述、实测数据 |
| `README.md` | **文档唯一入口** | 导航、分区表、写作与维护规范 | 规则与结论正文 |
| `research/NN-<主题>.md` | **跨特性底座的结论真源**（一册一主题） | 当前结论、当前实测证据、已否决方向、落地位置、未定项指针 | 决策过程、时间线、被取代的旧结论、派生快照 |
| `architecture.md` | **代码分层与依赖方向的唯一出处** | 层怎么切、依赖方向、两条触发路径、运行时形态 | 规则正文（属 `AGENTS.md` §4）与设计结论的复述 |
| `open-questions.md` | **未定项唯一清单** | 尚未决定的条目，及每条阻塞了什么 | 已决定的结论（决定后移入对应册或 `design.md`） |
| `contributing.md` / `security.md` | 贡献指南与安全政策的**正文** | 流程、报告方式、责任边界 | 规则与结论复述 |
| `../specs/` | 规格驱动开发的载体 | 每个特性一个目录：`spec.md` / `design.md` / `plan.md` / `tasks.md` | 实现代码 |
| `../skills/` | 可复用的固定流程 | 有固定步骤与固定验收标准的工作 | 一次性任务说明 |

**六册主题（`research/`）**：交付与部署 / 运行时与调度 / 依赖与工具链 / 安全与审查 / 开发与构建环境 / 命名、许可与治理。**一册一主题，同一结论只允许有一个出处**：跨特性底座按册，某特性的设计结论以该特性的 `specs/<特性>/design.md` 为唯一出处；跨文件只给指针，不复述。

## 4. 写作规范（`docs/` 下所有文件）

1. **只写当前有效的内容。** 决策变了就**就地改写**那一条；被取代的旧结论、旧编号**直接删除**，历史交给 git。**不写"已过时"段落，也不保留旧版本**——文档一旦膨胀就没人维护。
2. **不写时间线、不写决策过程。** 禁止出现「之前是……后来改成……」「经讨论」「现阶段暂定」这类措辞；读者只需要当前结论。
3. **一个出处。** 跨特性底座按 `research/` 一册一主题；某特性的设计结论以该特性的 `specs/<特性>/design.md` 为唯一出处。同一结论只允许有一个出处；其他文件只给指针（写成仓库相对路径）。
4. **未定项只登记在 `open-questions.md`**，不要在册里写成结论、也不要挑一个「合理的默认值」。
5. **语言与编码**：正文全部中文、中文标点（代码标识符、命令、路径、包名、外部术语保留原文）；文件名与目录名一律 **ASCII**；UTF-8 无 BOM + LF。
6. **不写没验证过的具体值。** 版本号、digest、地址、端口，未确认前写成占位或明确标注未定，**不要编造一个看起来确定的数字**。
7. **不得写入内网地址、主机名、端口、账号或任何真实凭据**——一律用占位符。
8. **没有编号式决策文件。** `docs/adr/` 已取消：不要再新建编号文件，也不要在任何地方写 `ADR-NNNN` 这类引用（见 `AGENTS.md` §6）。
9. **文档与代码不一致时以代码为准**，并提一个修正文档的改动。

## 5. 维护规范

- **结论变了**：按 `AGENTS.md` §6 改写它的落点（跨特性底座是 `research/` 下对应册，特性设计结论是该特性的 `specs/<特性>/design.md`）的那一条（含「已否决方向」），并检查是否有别处复述了它。
- **未定项被决定**：从 `open-questions.md` **移除**该条，把结论写进它的落点（对应册或该特性的 `design.md`）；两处并存即视为文档缺陷。
- **新增主题**：新建 `research/NN-<slug>.md`（`NN` 两位递增），并登记到本文件 §3；同时更新 `AGENTS.md` §1 的导航表。
- **文档自检**：全仓不得残留 `docs/adr/` 引用、`ADR-` 编号、「完全离线」这类已被更正的旧表述；发现即修。
