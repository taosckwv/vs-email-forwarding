# 未定项清单

本文件是**未定项的唯一清单**：只记录**尚未决定**的问题，每条写清「未定什么」与「阻塞什么」。

**处理约定**

- **一旦决定：从本文件移除**，并把结论写进 `docs/research/` 下对应主题册的「结论」段（被否决的方向写进「已否决方向」段）。**两处并存即视为文档缺陷。**
- **未定项不允许 AI 自行决定**：写代码时若发现「必须现在选一个」，就停下来问所有者，不要用「合理的默认值」糊过去（见 `AGENTS.md` §2）。这类默认值一旦落到表结构或接口上，改回来的代价极高。
- 已经定下来的**机制与结论不在本文件复述**，只给指针；本文件的内容是**尚未确定的形态与取值**。

> **阶段**：预研阶段已收口，正在进入需求阶段。实现细节（表结构字段、接口字段契约、校验强度、错误码分类等）在本文件**只登记、不决定**。
> 各条目的编号（`A1`、`D2` …）只是**引用用的把手**，册里的「未定项」段用它指向本文件。

## A. 数据模型与流水线

### A1. 三张邮件表的最终字段

- **未定**：待审表与邮件表的字段清单；`message_id` / `in_reply_to` / `references` 的存储与唯一性约束；线程关联字段（回复指向哪封原始出站邮件）的命名与语义。
- **已定的部分**（表形态）见 `docs/research/02-runtime-and-scheduling.md`。
- **阻塞**：首次 Alembic 迁移、ORM 模型与整个仓储层——**这是需求阶段的第一个入口**。

### A2. `rejected` 表保留什么、是否对外可查

- **未定**：是否保留邮件完整原文（还是只存 id + 原因 + 时间）；拒审原因是否通过 `GET /v1/messages/{id}` 暴露给调用方。
- **阻塞**：拒审路径的可观测性；若不保留原文，误判将无法复核、无法补发。

### A3. 审查通过后，待审行是否物理删除

- **未定**：是在单个事务内「删除待审行 + 写入目标表」，还是只标记状态不删除（保留待审行历史以便完整追溯）。
- **注意**：本条**没有任何默认值**，不要按「删除」实现。
- **阻塞**：待审表的清理策略与增长控制。

### A4. IMAP 游标与幂等键的**形态**

- **已定机制**（游标管效率、唯一键管正确性；`Message-ID` 不得用作幂等键）见 `docs/research/02-runtime-and-scheduling.md`。
- **未定**：独立 `imap_cursors` 表，还是通用 KV 表；是否需要支持多邮箱。
- **阻塞**：入站拉取流实现与首次迁移。

## B. 邮件收发与路由

### B1. 发件人与回复路由的剩余细节

- **已定**（`From` 固定取服务配置、服务端显式写 `Reply-To`）见 `docs/research/04-security-and-review.md`。
- **未定**：① `REPLY_TO_ADDRESS` 与 IMAP 账号**一致性的保证方式**（启动即失败 / 启动告警 / 仅人工保证）；② IMAP 登录名不是邮箱地址时的映射方式。

### B2. SMTP 与 IMAP 的真实参数

- **已定**：账号与密码由所有者提供；**证书信任随账号一并确认**（若为私有 CA，需要把根证书带入宿主 / 镜像）。
- **未定**：SMTP 主机 / 端口 / 是否 STARTTLS；IMAP 主机 / 端口 / 专用回复邮箱地址 / 目标邮箱文件夹；证书信任的具体内容。
- **当前状态**：全部收敛到 `.env`，仓库只提供 `.env.example` 占位值。
- **阻塞**：真实环境联调。

### B3. 发信失败的重试与终态

- **已定**（3 次、15s / 30s / 60s、终态失败）见 `docs/research/02-runtime-and-scheduling.md`。
- **未定**：SMTP 返回码的分类策略（永久性错误是否直接置 `failed` 而不重试）；达到上限后是否需要通知调用方。
- **阻塞**：状态机实现与写库字段（`attempt_count` / `next_attempt_at` / `last_error`）。

## D. 环境与部署

### D1. 基础镜像 tag 的 digest 复核

- **待复核**：`python:3.13-slim-trixie`、`ghcr.io/astral-sh/uv:0.12.20`、`postgres:17` 写进脚本之前，逐一复核 digest 是否仍是预期值。
- **为什么不能省**：基础镜像靠 tar 往返交付，浮动 tag 与 digest 都会随时间漂移。
- **不阻塞**：可以按现 tag 先写，落笔时复核一次。

### D2. 部署脚本的具体形态（**新链路脚本尚未实现**）

- **已定**（服务器本地构建 + 基础镜像以 tar 带入；`deploy/` 当前只有职责 README）见 `docs/research/01-delivery-and-deploy.md`。
- **阻塞**：任何实际部署。

### D4. 数据库备份、日志采集与保留期

- **未定**：生产数据库的备份方式、频率与恢复演练；应用日志如何采集（`docker logs` + journald 还是集中式）；日志与数据的保留期。
- **阻塞**：运维文档（`docs/deployment.md` 尚未撰写）。

### D5. 邮件数据的保留期与清理策略

- **未定**：邮件表与 `rejected` 表是否需要定期归档或清理、保留多久、是否有合规要求的保留期限。
- **处理状态**：所有者已明确推迟到设计阶段；本条**保持未决**，不要当成已定。
- **阻塞**：是否需要引入定期清理任务（会成为第五条流）。

### D6. 本地邮件捕获工具是否采用 Mailpit

- **未定**：开发环境是否用 Mailpit（同时提供 SMTP 与 IMAP，用于验证「发出去 → 被拉回来 → 关联上原邮件」的完整回路）；候选镜像已确认存在且活跃。
- **备选**：其他本地捕获方案；或不做本地捕获、集成测试直接打真实邮件服务器（不推荐）。
- **注意**：本机装不了 Docker Desktop，因此本地捕获**目前无法在本机验证**（见 `docs/research/05-dev-and-build-environment.md`）。
- **阻塞**：`compose.dev.yaml` 的最终内容与集成测试方案。

### D8. 服务器侧 Docker 是否有可升级路径

- **待确认**：Docker 官方已不再支持 CentOS 8 作为宿主；服务器上这版 Engine 构建于 2024-05-16，容器运行时补丁停在该时间点（**不预设存在任何具体漏洞**）。
- **不阻塞**：属中长期运维与安全风险，留待所有者评估。

### D12. 宿主 yum 源版本与发行版不匹配的风险

- **风险**：宿主当前配置的 yum 源是 CentOS **8.5** 的 vault，而宿主发行版实测为 **8.2.2004**；从 8.5 源安装宿主包，可能顺带把部分系统包乃至内核升到 8.5 —— 在这台**已 EOL** 的生产机上，这属于**未授权的局部升级**。
- **未定（两条方向，由所有者选择）**：① 改用与宿主版本匹配的 8.2 vault 源；② 用已挂载的 CentOS 8.2 安装 DVD 配成本地 repo（包版本与宿主完全匹配，且不需要公网）。**同时未定**：该本地 repo 是否长期保留、ISO 与挂载点在重启后是否仍可用、具体要离线安装哪些包。
- **硬约束**：**在服务器上安装任何宿主包之前，必须先看本条。**

### D13. 基础镜像 tar 由哪台机器、用什么工具产出

- **未定**：「外部机器」具体是哪一台（开发机没有 Docker；服务器又拉不到内网 Docker 源）、用什么工具产出 tar 与 sha256 旁路文件。
- **已定**：基础镜像必须由外部以 tar 形式带入（内容见 `docs/research/01-delivery-and-deploy.md`）。
- **阻塞**：D2 的打包脚本无法动笔。

### D14. `docker save` 是否可放宽使用 `--platform`

- **未定**：现行结论是「`save` / `load` **一律不传** `--platform`」（服务器 API 1.45 不支持该参数，且刻意不让交付链的任何一环依赖 Engine ≥28）；而归档自检脚本的处置建议里出现过「产出方 CLI ≥28 时可用 `--platform`」。在**产出方未定**（D13）的前提下，是否放宽需要所有者裁决。
- **当前执行口径**：**一律不传**。

### D15. PostgreSQL 数据目录是否落在独立盘 `/data`

- **未定**：宿主另有一块 256G 的 ext4 盘挂在 `/data`，磁盘布局允许把数据目录放过去；是否这样做属于部署形态，待所有者确认。
- **阻塞**：compose 的挂载路径与未来的数据迁移方式。

## E. 依赖与工具选型

### E1. IMAP 客户端选型

- **候选**：`imapclient`（同步，在 asyncio 中需要放到线程池）；`aioimaplib`（原生异步，但未声明支持目标 Python 版本，且长期未发新版）。
- **未定**：选哪个。
- **阻塞**：入站拉取流实现。

### E2. `httpx` 与 `httpx2`

- **现状**：`httpx` 在目标 Python 上**实际可用**（测试已跑通），但 FastAPI / Starlette 已发出弃用提示，上游在推进 `httpx2`。
- **未定**：现在就跟进 `httpx2`，还是等 FastAPI 正式移除 `httpx` 支持时再迁移。
- **这属于依赖替换**（`AGENTS.md` §6 的不可逆决策范畴），必须由所有者决定。
- **阻塞**：测试依赖的锁定方式。

### E3. 数据库驱动

- **已定**：PostgreSQL + Alembic 作为迁移工具（见 `docs/research/02-runtime-and-scheduling.md`）。
- **阻塞**：运行时依赖清单与首次迁移。
