# 0005. 部署形态：CentOS 8 + 完全离线 + Docker 容器

- 状态：已接受
- 日期：2026-09-29
- 决策者：项目所有者

## 背景

生产环境由项目所有者指定：**最终运行在 CentOS 8 上**，服务器**完全离线**（不能访问公网 PyPI / GitHub），服务器上**已安装 Docker 并可正常使用**，IP 与端口后续提供。

这几个前提叠加后产生过一个真实冲突：所有者最初同时选择了「完全离线」「生产 CentOS 8 本机安装 PostgreSQL」与「Docker 容器」——离线安装 PostgreSQL 的 RPM 需要处理 vault 源与一整套相互依赖的包，而容器方案下 PostgreSQL 只是一个镜像，两者相互矛盾。

另外两个已确认的平台事实：

- CentOS 8 与 CentOS 8 Stream **均已 EOL**（分别于 2021-12-31 与 2024-05-31），官方源已迁至 vault，**不再有安全更新**。所有者明确知悉并接受，系统不做变更。
- CentOS 8 的系统 Python 是 **3.6.8**，无法运行本项目。

## 决策

- **生产目标平台：CentOS 8，系统保持不变**（接受无安全更新这一后果）。
- **完全离线部署**：服务器不访问公网。
- **应用以 Docker 容器运行**；**PostgreSQL 同样以容器运行在同一台机器上**，数据卷挂载到宿主机目录持久化。
- **交付流水线**：开发机 `docker build` → `docker save` 为镜像 tar → 通过介质/跳板机传输 → 服务器 `docker load` → 用 compose / 运行脚本启动。
- **交付物仅为镜像 tar + 运行脚本**；服务器上**不需要 Python、不需要 uv、不需要联网**。数据库迁移通过 `docker run --rm <镜像> alembic upgrade head` 在容器内执行。
- 配置全部走 `.env`（`HTTP` 监听、SMTP/IMAP 主机与账号、数据库连接串、发件人地址、轮询间隔），仓库只放 `.env.example` 占位。

## 后果

### 正面

- 服务器零 Python 依赖：规避了 CentOS 8 系统 Python 3.6.8 与离线装 Python 的全部麻烦。
- 环境被封装在镜像里，开发机与生产之间的差异被压到最小（见 ADR-0006 关于「宿主与容器内发行版相互独立」的说明）。
- 数据持久化只涉及一个宿主机目录，备份与迁移路径清晰。
- 把 PostgreSQL 也容器化，彻底绕开了离线 RPM 依赖问题——这是本决策中对原方案的关键修正。

### 负面 / 代价

- **每次发版都必须走一遍 save / 传输 / load 介质流程**，无法在线热更新，发布节奏受人工步骤限制。
- 服务器上无法直接修改或调试应用代码，排障只能靠容器日志与应用自身输出。
- **CentOS 8 无安全更新**，宿主层漏洞只能靠限制网络暴露面来缓解（所有者已明确接受）。
- 首次传输的镜像体积较大，`docker save` 的 tar 包含全部层，介质容量与传输时间需要考虑。
- 镜像内基础层的 Debian 版本若随 tag 漂移，会引入不可见的环境变化，因此必须锁 tag 或 digest（见 ADR-0006）。

## 备选方案与被否决的原因

| 方案 | 否决原因 |
|---|---|
| 宿主机离线安装 PostgreSQL RPM | 需要先在内网搭好 vault / PGDG 本地源并凑齐依赖包，工作量和风险都落在所有者一侧；且与「应用跑 Docker」的方案形成两套交付物（镜像 + RPM 集），明显更复杂。取舍为把 PostgreSQL 也容器化。 |
| 宿主机直装 Python 运行应用 | CentOS 8 系统 Python 为 3.6.8，无法运行 FastAPI 与 Python 3.13 代码；离线获得新的 CPython 比打镜像更麻烦。 |
| 用 podman 替代 Docker | CentOS 8 自带 podman 而不带 docker，本可作为「不额外安装容器运行时」的方案；但所有者明确选择 Docker 容器，且服务器上 Docker 已装好，因此未采用（podman 作为将来可能的备选保留）。 |
| 内网私有 registry 分发镜像 | 服务器完全离线，registry 不可达。 |
| 内网专用构建机 | 所有者选择在开发机构建；开发机可联网拉取基础镜像与依赖，符合「构建时联网、运行时离线」的划分。 |
| 不用容器，交付源码 + 离线 wheels + 独立 CPython + systemd | 与所有者选定的 Docker 方案直接矛盾。 |
| 迁移到 Rocky / Alma 9 以获得安全更新 | glibc 2.34 会让几乎所有新 wheel 直接可用，且有安全更新；但所有者选择「就 CentOS 8，系统不变」。 |
