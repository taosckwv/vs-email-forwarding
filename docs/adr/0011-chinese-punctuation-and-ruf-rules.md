# 0011. 中文标点与 ruff 的 RUF001/002/003 规则例外

- 状态：已接受
- 日期：2026-09-29
- 决策者：项目所有者

## 背景

本仓库明确要求「文档与注释内容全中文」（见 `AGENTS.md` §7 编码约定与 `docs/README.md` 写作规范第 1 条）。

而 ruff 的三条规则与这一要求存在**前提冲突**：

| 规则 | 检查对象 |
|---|---|
| `RUF001` | 字符串中存在与 ASCII 混淆的歧义字符（ambiguous-unicode-character-string） |
| `RUF002` | docstring 中存在与 ASCII 混淆的歧义字符（ambiguous-unicode-character-docstring） |
| `RUF003` | 注释中存在与 ASCII 混淆的歧义字符（ambiguous-unicode-character-comment） |

这三条规则的设计前提是**代码里使用 ASCII 标点**，因此把全角中文标点（`：`、`；`、`，`、`（`、`）` 等）判定为「有混淆风险的歧义字符」。

**实测（在真实环境跑门禁的结果）**：

- `ruff format --check`：通过
- `mypy src`：通过（15 个源文件零问题）
- `pytest`：通过（1 passed）
- **`ruff check .`：176 个错误，全部是 `RUF001` / `RUF002` / `RUF003`**

176 处告警**全部来自中文注释、docstring，以及 `main.py` 中提供给 FastAPI 的中文 `description` 字符串**——即全部来自「按项目要求写的中文内容」。**零处来自代码逻辑，代码本身没有任何问题。**

因此这不是代码缺陷，而是一个**决策冲突**：项目要求中文，规则假设 ASCII。

## 决策

- 在 `pyproject.toml` 的 `[tool.ruff.lint] ignore` 中**显式加入 `RUF001`、`RUF002`、`RUF003`**，并在配置旁保留注释说明理由——**因为本仓库强制中文标点，这三条规则在此语境下不适用**。
- **其余规则一律不放宽**：同一次改动不得顺带忽略任何其他规则；`ruff` 的其余全部检查、`mypy`、`pytest` 的标准都保持不变。
- `pyproject.toml` 的该项改动由项目所有者执行。**本 ADR 是该改动的前置记录。**

### 这不是「为了过门禁而放宽配置」

`AGENTS.md` §10 明确禁止「为了让门禁通过而放宽 ruff / mypy 配置」，§6 要求此类不可逆改动**必须先写 ADR 再动手**。

本条 ADR **不是绕过那道禁令，而是执行那道禁令所要求的程序**。两者的区别在于冲突的性质：

- 被禁止的情形是：**代码质量不达标**，为了让门禁变绿而降低标准。
- 本条的情形是：**「中文标点」这一明确的项目决策，与「规则假设 ASCII 标点」这一工具前提相互矛盾**。此时正确的处置是**显式记录例外**，而不是反过来修改代码去迎合工具。

**本 ADR 的存在本身就是 §10 所要求的前置条件**——即：门禁标准的任何放宽，必须有据可查、有理由、且经过记录，而不是一段无解释的配置改动。

## 后果

### 正面

- 中文注释、docstring 与中文 API 描述字符串可以自然书写，不必在每个中文句子里混用 ASCII 标点。
- 不需要向新贡献者与 AI 交代一条「写中文但标点必须用英文」的特殊约定——这类约定正是「用人力对抗工具」，长期必然失守。
- 其余 RUF 规则（例如 `RUF100`「无用的 `noqa`」）仍然生效，规则覆盖面只损失被显式列出的三条。
- 例外被记录在案：将来有人问「为什么这里 ignore 了三条规则」，答案可查。

### 负面 / 代价

- **从此这三类「全角字符混入代码」的问题不再被自动发现**。具体地说：若将来有人把全角标点写进**代码标识符或字符串字面量**（而不是注释 / docstring），门禁不会再报。
- 该例外是**全局的**（整个仓库生效），不是按文件或目录限定，因此无法只对注释放宽而保留对字面量的检查。
- 缓解方式：
  1. 代码审查时**人工留意标识符与字符串字面量中的全角字符**；
  2. 除这三条外的规则仍然生效（例如 `E501` 行长限制）；
  3. 若将来真的出现「全角字符进入标识符或字面量」的实际案例，应改为更精细的 `per-file-ignores` 或前缀级忽略，而**不是继续维持全局忽略**——届时需要新开一个 ADR 取代本条。

## 备选方案与被否决的原因

| 方案 | 否决原因 |
|---|---|
| 把代码中的中文标点全部改成 ASCII 标点 | 会让中文 docstring 的可读性明显变差；更严重的是要求每一位新贡献者、每一次 AI 生成都记住这条特殊约定——属于用人力对抗工具，长期必然失守。 |
| 把这三条规则降级为 warning | **ruff 没有 warning 级别**，只有「选中 / 忽略」两种状态，该方案在工具层面不成立。 |
| 整体关闭 RUF 规则族 | 过度放宽：会连带丢掉 `RUF100`（无用的 `noqa`）等真正有价值的检查。 |
| 用 `per-file-ignores` 逐文件忽略 | 告警分布在大量文件中且会随新增文件持续增长，逐文件维护的成本高于收益；且它并不比全局忽略更安全（问题的本质是标点字符集，不是文件）。 |
| 不写 ADR，直接改 `pyproject.toml` | 违反 `AGENTS.md` §6「不可逆决策必须先写 ADR 再实现」，并会让门禁标准在无人察觉的情况下漂移。 |
