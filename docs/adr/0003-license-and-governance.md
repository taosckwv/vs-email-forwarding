# 0003. 许可证与治理：MIT + 私有仓库按开源规范

- 状态：已接受
- 日期：2026-09-29
- 决策者：项目所有者

## 背景

项目所有者的要求是「不要参考本地的其他项目，按照开源项目的标准来」。这意味着即使仓库当前私有，也要把开源项目应有的治理文件与流程立起来。否则将来若要公开，会面临补历史、改提交规范、重写 CHANGELOG 的返工。

## 决策

- **许可证：MIT**，仓库内放完整 `LICENSE` 文本。
- **可见性：私有仓库**，但**完全按开源规范治理**。
- **托管平台：GitHub**（本机已有可用的 SSH 密钥；不安装 `gh` CLI 也能推拉）。
- **制品：暂不发布**（不发布到公共或内部 registry）。
- 治理文件：`README.md`、`CONTRIBUTING.md`、`SECURITY.md`、`CHANGELOG.md`、`.github/PULL_REQUEST_TEMPLATE.md`、`.github/ISSUE_TEMPLATE/`。
- 流程规范：Conventional Commits（**中文描述**）+ commitizen 校验 + 手工维护 CHANGELOG + 语义化版本 + `docs/adr/` 记录不可逆决策。

### 所有者已知悉的事项

- **MIT 意味着未来一旦仓库转为公开，任何人都可以商用**（包括闭源商用）。许可证管的是使用许可，与仓库可见性无关，因此「私有仓库 + MIT」并不矛盾。
- 私有阶段这些社区治理文件（CONTRIBUTING、Issue 模板等）不会带来外部贡献者，它们的价值在于**流程约束与未来公开时的零返工**。
- 如果最终确认此项目永不公开，正确的许可证应是 `Proprietary / All rights reserved`，而不是 MIT；届时需要新开一个 ADR 取代本条。

## 后果

### 正面

- 未来把仓库转 public 不需要补任何治理文件，也不需要重写提交历史（提交信息从第一个提交起就符合 Conventional Commits）。
- 提交历史可读，CHANGELOG 可人工汇总。
- PR 模板强制关联 spec 编号，使改动可追溯到需求（配合 ADR-0004）。

### 负面 / 代价

- MIT 不含专利授权条款，企业法务在正式采用时可能要求换成 Apache-2.0。
- 手工维护 CHANGELOG 依赖人的自觉，没有工具兜底（因为不跑 CI，社区常用的自动生成方案不适用，见 ADR-0010）。
- 私有仓库下「开源规范」的部分收益是延迟兑现的（要等到公开才体现）。

## 备选方案与被否决的原因

| 方案 | 否决原因 |
|---|---|
| Apache-2.0 | 含显式专利授权，更适合会被企业内部系统依赖的基础设施项目，故曾作为首推；但项目所有者选择 MIT。 |
| AGPL-3.0 | 能防止云厂商闭源白嫖，但会显著提高企业采用的心理与法务门槛。 |
| Proprietary / All rights reserved | 若确认永不公开，这才是正确选项（且应同时去掉社区治理文件）；所有者选择了 MIT，即隐含保留了未来公开的可能。 |
| 公开到 GitHub | 所有者选择先私有；公开会要求从第一个提交起就更谨慎地处理内部信息。 |
| 发布制品到 registry | 私有阶段无发布对象，且会引入 token 与兼容性承诺的额外负担。 |
